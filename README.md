# 衡资 0.2.1

Node.js 22.5+；无需第三方 npm 依赖。

## 启动

```bash
git clone https://github.com/jiaqiang-coder/finance-management.git
cd finance-management
read -rsp '衡资访问密码: ' APP_PASSWORD; echo
APP_PASSWORD="$APP_PASSWORD" npm start
unset APP_PASSWORD
```

必须提供独立的 APP_PASSWORD。未设置、留空或使用历史开发密码时，服务会拒绝启动。真实密码只保存在服务器配置中，请勿提交到 Git 或打包分享。默认监听 127.0.0.1:4173。访问路径为 /app/fm/，生产需通过 HTTPS 代理访问。

## 本次完善

- 新增及编辑资产/负债账户：名称、分类、币种、原币金额、备注、估值方式。
- 人民币、美元、港币录入；自动模式由服务端折算，不信任客户端人民币估值。
- 汇率管理：官方报价日、获取时间、来源、最近90个报价日历史、最近7次自动同步状态。
- 欧洲央行 ECB 官方 XML：https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml 。以欧元参考汇率交叉计算 USD/CNY 与 HKD/CNY。
- 每天北京时间01:10自动同步。服务器晚启动会补跑当天任务；失败会记录，保留旧值，可手动重试。周末及休市日沿用最近交易日报价，不冒充当日报价。
- 原有账户默认保持手动估值；编辑时可改为自动。更新只重估自动模式账户，不改历史流水。
- 不再自动填充演示数据；历史趋势尚未实现，显示明确空状态，移除虚构指标。

## 持久化

SQLite：data/hengzi.db。汇率缓存、报价历史、自动任务状态均入库。Docker需挂载此目录；重启/更新不要删除该目录。持久化不等于备份。

## 更新已有服务器

将同包 hengzi-display-fix.py 上传到服务器 /tmp，执行 sudo python3 /tmp/hengzi-display-fix.py。脚本会备份数据库与旧代码，保留现有业务记录，更新衡资源码后重启 hengzi-fm。不会修改博客、sub2api 或 Caddy。完成后强制刷新浏览器。

## 验证

项目目录执行 npm test；前端逻辑测试使用 DOM 桩，接口测试使用临时数据库与确定性ECB格式样本，包含更新失败、账户编辑及进程重启持久化。测试不等于线上浏览器验收。

历史估值趋势、PDF报告、真实证券行情、自动备份和正式身份系统仍需完善；不以演示数值代替真实数据。收支报告当前的服务端日期范围仍为原版本固定月份，后续需改为动态统计周期。

## 预算设置

在预算预警页点击预算设置可新增分类预算，也可选择已有预算或点击分类行的编辑按钮修改。金额为人民币，必须大于0；预警阈值为1%至100%。分类名需与流水分类一致；同名分类不可重复创建。预算支出按北京时间当前自然月统计，修改后会重新计算总览预警。

## 日终资产趋势

首页支持近 7、30、90 天的总资产、总负债和净资产，按人民币或美元展示，可选择某天查看账户明细。今天单独显示为未结算。

- 第一次启动写入当前账户的初始版本，统计从启用当天开始。启用前不生成快照。
- 按北京时间午夜切分日期。记录账户状态和汇率的变更时间，用截点前的最后版本生成快照；服务恢复后可补齐启用以来漏跑的日期。
- 历史金额和报价日冻结。人民币采用账户当时已保存的估值；美元使用截点前可用的美元汇率折算，缺汇率的日期留空。
- 汇率影响以当前账户组合、前日可比账户汇率计算；手动估值和不可比账户的估值变动归入其他变动。美元口径还包含报告币种转换的影响。其他变动不等同投资收益。
- 版本及快照存于现有 SQLite 文件，升级时自动建表，不需要导入历史数据。

## 首页智能记账与 CSV

- 首页「说一句，记一笔」支持浏览器语音转写和文字输入。新增及修改在核对后才写入 SQLite；查询只读，按原币汇总。可试「昨天午饭花了 48 元」「这周餐饮花了多少」「把昨天那笔午饭改成 58 元」。
- 默认用本地规则处理常见表达。不支持语音的浏览器可以打字。浏览器的语音识别可能由浏览器厂商在线处理。
- 需要更灵活的自然语言时，可在服务器的私有环境配置里同时设置 `HENGZI_AI_MODEL` 和 `HENGZI_AI_API_KEY`，可选设置 `HENGZI_AI_CHAT_URL`（HTTPS 的 Chat Completions 完整地址，默认使用 OpenAI）。只提交当前输入句子和日期上下文给模型，不发送账本或账户列表。模型只解析意图，不能写账；超时或失败时回退到本地规则。密钥不要提交 Git。
- 批量导入支持 UTF-8 / GB18030 CSV（最多 900 KB、5000 条）。通用表头至少包含日期、金额、收支类型；支持交易方、分类、账户、币种和备注。Excel 文件先另存为 CSV。预览后确认才写入；格式有错时不导入任何行。
- 流水页可下载全部流水 CSV，文件可再次预览导入；已有的相同记录按条数去重。报告可导出所选周或月的分币种、分分类 CSV。首页收支和人民币预算只汇总人民币流水。

## 0.3.0 页面与投资账本

- 资产总览采用全宽日终趋势，纵轴显示金额、币种与日期；可点击或用键盘选择日期。变化金额以正负号和颜色区分，零变化淡化；账户明细默认收起。
- 语音／文字记账与最近流水移至「收支流水」。分析报告拆为资产分析、收支分析；汇率与预算保留。
- 新增「金融投资」：投资总览、我的持仓、收益与风险、交易记录。未加入 AI 投资研究，也不会向券商下单。
- 首次使用：新建投资账户，或明确确认关联已有股票资产（替代其手工估值，避免重复统计）；录入各币种期初现金、股票数量及平均成本。期初股票不再扣现金，原资产快照保留。关联后请完整录入余额和股票，补录完成前估值可能暂时偏低。
- 日常维护：记录买入、卖出、入金、出金。按日期顺序保存；买入费用计入平均成本，卖出费用从已实现盈亏扣除；禁止现金不足买入、超量卖出和未来日期。只可撤销该账户最近一笔，撤销保留审计记录，可重新录入。
- 原币现金分别维护；本版不支持融资、卖空、自动换汇、分红／拆股公司行动或券商自动同步。入金／出金不自动修改另一个银行账户，跨账户转账需要核对两边记录。没有完整历史账单时不展示累计收益率。
- 页面显示原币盈亏与按当前参考汇率折算的人民币盈亏；这不是严格的历史汇兑收益归因。外币报价与汇率缺失时不伪造估值，保留资产总览的上次估值并提示。

### 行情连接

在服务器私有服务环境配置 `HENGZI_MARKET_API_KEY` 可启用 Twelve Data `/time_series` 日线接口；每天北京时间 10:00 后同步一次（失败最多重试三次，间隔一小时），停机后当天恢复会补跑。也可在持仓页手动刷新（间隔至少一分钟）。市场覆盖、证券代码与交易所标识、授权和延迟以供应商订阅为准；并非所有市场免费实时。官方文档：<https://twelvedata.com/docs>。

界面录入的代码必须与供应商该交易所代码一致。返回价格、币种、证券代码、交易所及时间均需校验；异常或较旧报价保留上次结果。服务端密钥不返回前端、不进入仓库。未配置服务时，可在持仓行手工维护参考报价；成交价／成本价仅作明确标注的初始参考，不冒充实时行情。

### 升级与验证

运行 `npm test`；新增 HTTP 投资测试覆盖账户关联、现金／成本／盈亏、重复提交、非法交易、撤销回算、行情失败和进程重启。测试使用临时数据库和确定性供应商响应；不代表真实行情订阅已开通。

升级只追加 investment_* 表，不清空原表，不回填启用日前历史数据。生产更新前备份现有 SQLite（包括一致性处理 WAL），保留 data 目录。自动部署仍只更新既有四个运行文件，无新增 npm 运行依赖。

估值口径：按北京时间的前一天作为日期上限，取各交易所当地交易日的最近一个收盘价；周末／休市沿用上一个交易日。明确请求不复权日线，不将盘中价格当收盘价。自动同步成功后当天不重复运行，重启后仍保留状态。手动参考价或录入价在启用日线同步后被该收盘价替代，页面保留实际交易日，不假装每次刷新都有新报价。

## AI 助手（0.4）

首页的「AI 助手」可展开对话窗口，手机上全屏展示。支持历史对话、查询依据、资产/负债与持仓分析、按币种统计收支、预算核对、日终趋势，以及根据用户明确提供的月度必要开支比较现金储备方案。数值由应用工具读取或计算，模型组织分析。没有互联网搜索能力，不应当作实时行情或最新政策研究。

首次打开「AI 设置」，填写完整 HTTPS Chat Completions 地址、模型名称和 API Key，再保存并测试连接。可以使用 sub2api 等兼容网关；模型必须支持 `tools` / `tool_calls`。不固定或内置任何付费模型。也支持既有环境变量 `HENGZI_AI_MODEL`、`HENGZI_AI_API_KEY`、`HENGZI_AI_CHAT_URL`；界面保存的配置优先。现有自然语言记账意图解析也复用该配置。

- **数据范围**：仅向配置的服务商发送提问、最近12条已完成对话及本次工具结果，不会把整库文件或密钥放入模型消息。使用前应在设置里确认数据发送目的地。API 额度独立于聊天产品订阅。
- **密钥**：界面保存后不回显、不进入浏览器存储；使用基于 `APP_PASSWORD` 的 scrypt 派生密钥及 AES-256-GCM 加密入库。更换登录密码后须重新保存模型配置。环境变量中的密钥仍由运维环境管理。
- **执行边界**：模型可查询、计算和生成草案，不能直接执行 SQL、买卖证券或转账。当前可预览并确认修改非投资关联账户的分类，以及已有收入/支出流水的分类、摘要与金额。确认前不会改账；确认时校验原记录未变化，重复确认幂等，草案24小时过期，记录修改前后值与确认状态。
- **报告**：对有查询依据的已完成分析，可保存为报告、回看当时数据依据并下载文本。历史报告为生成时快照，不随当前余额变化。
- **限额与失败**：每个会话同时1次分析、全局最多2次；一次最多5次模型请求、12次工具调用。每个模型请求45秒超时；无配置、鉴权失败、限流、结果异常会明确提示，不伪造分析结果。重启会将未完成分析标为中断。

`ai_threads` / `ai_messages` / `ai_actions` / `ai_reports` / `ai_settings` 保存在既有 SQLite 数据库，升级为增量建表，不修改原账本或历史日终快照。测试中的 `tests/ai_provider_fixture.cjs` 仅由隔离测试显式加载，生产启动不会加载模拟模型。
